# 日志系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpower-subagent-driven-development (recommended) or superpower-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给程序装上系统级日志：要打的地方 `logger.info("...")`，同时写控制台与 `logs/screener.log`，文件留全量细节、控制台只留进度。

**Architecture:** 标准库 `logging`，两个 handler 挂在 `screener` logger 上：`FileHandler`（门槛 DEBUG，utf-8，追加）+ 自定义控制台 handler（门槛 INFO，正文交给注入的 `output_fn`，并丢掉异常堆栈）。各模块用 `logging.getLogger(__name__)` 打日志，`sync_all` / `fetch_datasets` 的签名不动。控制台上每条信息只出现一次：日志行取代了三处现有 `output_fn(...)`。

**Tech Stack:** Python 3.13、标准库 `logging`（零依赖）、`unittest`、Ruff。

**Spec:** `docs/superpowers/specs/2026-10-18-logging-design.md`

## Global Constraints

- Python 3.13，**只用标准库**：日志用 `logging`，不引入 `loguru` / `structlog`
- 测试用 `unittest`（不用 pytest）；跑法：`.venv\Scripts\python.exe -m unittest discover -s tests -t .`
- Lint：`.venv\Scripts\ruff.exe check --no-cache .` 与 `.venv\Scripts\ruff.exe format --check --no-cache .`。ruff 的缓存目录写不进去，**必须带 `--no-cache`**；`ruff format` 无法回写文件，按 `--diff` 输出手动改
- 控制台输出**只能**走注入的 `output_fn`，不许直接 `print` / 写 stdout
- 日志文件与控制台**都不许出现 token**
- 文件 handler 必须显式 `encoding="utf-8"`（Windows 上不给中文会坏）
- 门槛写死：文件 `DEBUG`、控制台 `INFO`。不做配置化
- 不轮转：一个系统级文件，只追加、不清空
- **不改** `sync_all` / `fetch_datasets` 的签名
- 文案与 spec §5 的事件清单**逐字一致**

## Review Focus

1. `log_file` 指向已存在的目录、或所在目录不可写 → `setup_logging` 直接抛 `OSError`，程序在打印菜单之前就退出，用户看不到任何提示。**明确接受**（与「不为小概率异常加防护」一致）。钉住：Task 1 `test_a_directory_as_log_file_is_not_swallowed`
2. `logs/screener.log` 无限增长，永不轮转、永不清理。**明确接受**（spec §4）。钉住：Task 1 `test_appends_instead_of_truncating`
3. 用户把 token 塞进 `TUSHARE_API_URL` → DEBUG 的「客户端就绪：地址 …」会把它写进日志文件。**不额外防护**（配置错误）。钉住：Task 3 断言该行不含 `tushare_token` 的值
4. 同一进程内 `main()` 被反复调用（测试、将来的批处理入口）→ handler 累积、控制台 handler 攥着上一轮的 `output_fn`。钉住：Task 1 `test_setting_up_twice_does_not_accumulate_handlers`，Task 5 的 `tearDown` 调 `shutdown_logging`
5. 没调 `setup_logging` 就直接用 `sync` 层（脚本、单测）→ INFO/DEBUG 静默丢弃，WARNING 及以上被 stdlib 的 lastResort 打到 stderr，测试输出会变脏。钉住：Task 3 给 `CallWithRetryTest` 装 `NullHandler`

- [ ] **Step 3: 实现 `screener/logging.py`**

文件 handler **先加**、控制台 handler **后加**：文件那个 formatter 会先把 `exc_text` 缓存在 record 上，控制台再复制 record 并清掉它。顺序反了堆栈会漏进控制台。

```python
import logging
from collections.abc import Callable
from pathlib import Path

LOGGER_NAME = "screener"
FILE_LEVEL = logging.DEBUG
CONSOLE_LEVEL = logging.INFO
FILE_FORMAT = "%(asctime)s %(levelname)-5s %(name)s  %(message)s"
FILE_DATE_FORMAT = "%Y-%m-%d %H:%M:%S"

_installed: list[logging.Handler] = []


class ConsoleHandler(logging.Handler):
    """把日志正文交给注入的输出函数；异常堆栈只留给文件。"""

    def __init__(self, console: Callable[[str], None]):
        super().__init__(level=CONSOLE_LEVEL)
        self._console = console

    def emit(self, record: logging.LogRecord) -> None:
        record = logging.makeLogRecord(record.__dict__)
        record.exc_info = None
        record.exc_text = None
        self._console(self.format(record))


def setup_logging(*, log_file: Path, console: Callable[[str], None]) -> None:
    """装上文件与控制台两个输出源；重复调用不会累积 handler。"""
    shutdown_logging()

    log_file.parent.mkdir(parents=True, exist_ok=True)

    file_handler = logging.FileHandler(log_file, encoding="utf-8")
    file_handler.setLevel(FILE_LEVEL)
    file_handler.setFormatter(logging.Formatter(FILE_FORMAT, FILE_DATE_FORMAT))

    console_handler = ConsoleHandler(console)
    console_handler.setFormatter(logging.Formatter("%(message)s"))

    logger = logging.getLogger(LOGGER_NAME)
    logger.setLevel(FILE_LEVEL)
    logger.addHandler(file_handler)
    logger.addHandler(console_handler)
    _installed.extend((file_handler, console_handler))


def shutdown_logging() -> None:
    """移除并关闭自己装的 handler，避免测试之间互相污染。"""
    logger = logging.getLogger(LOGGER_NAME)
    for handler in _installed:
        logger.removeHandler(handler)
        handler.close()
    _installed.clear()
```
