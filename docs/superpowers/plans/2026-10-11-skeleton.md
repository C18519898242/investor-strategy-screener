# 第一版程序骨架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpower-subagent-driven-development (recommended) or superpower-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出可以用 `python main.py` 启动的本机命令行骨架：菜单、SQLite 元数据、整次同步可见性和离线 HTML 都已接通，但第 1 集筛选公式与 Tushare 拉数尚未实现。

**Architecture:** 仓库根目录的 `screener/` 分成 `cli`、`sync`、`store`、`strategies`、`report`。策略通过登记项接入菜单和 HTML。同步批次只有发布之后才对筛选可见；筛选前先检查登记的数据是否完整。

**Tech Stack:** Python 3.13、标准库 `sqlite3`、`unittest`、`html`、`pathlib`；计算接口预留 `pandas.DataFrame`。不新增依赖，不调用 Tushare。

**Spec:** `docs/superpowers/specs/2026-10-11-tech-selection-architecture-design.md`

本计划只实现架构骨架。表名、字段、历史保留期限、Tushare 接口顺序和格雷厄姆公式留在下一份实现计划；实现本计划时不得提前决定这些内容。

## Global Constraints

- 语言是 Python，入口命令是 `python main.py`；源码不放进 `src/`。
- 本地数据是一个 SQLite 文件，路径固定为 `data/screener.sqlite3`，只用标准库 `sqlite3`。
- 不安装 SQLAlchemy、Jinja2、pytest、网页服务、Docker 或独立数据库。
- 只有 `screener/sync.py` 可以成为将来联网的位置。连接地址、Key 来源和客户端构造由 `docs/superpowers/plans/2026-10-11-tushare-connection.md` 规定；本骨架计划不实现具体数据接口，同步函数接收注入的 `fetch`，默认实现抛出 `NotImplementedError`。
- `screener/strategies/` 与 `screener/report.py` 的源码不得出现 `tushare`。
- Token 的环境变量名是 `TUSHARE_TOKEN`；不得写入代码、SQLite、HTML 或日志文本。
- 菜单一次只执行同步或筛选中的一件事。
- 筛选和重算不联网。空白日期本应读取本地交易日历；日历表尚未建立，因此空白日期报错，不得联网猜测交易日。
- HTML 使用 UTF-8 和内联 CSS，不引用外部字体、样式或脚本。
- 最终 HTML 只包含入选股票。无入选股票时原文显示“本次无符合条件的股票”。
- 开发测试使用 `python -m unittest`。测试通过不等于用户验收。

## Review Focus

- 同步写到一半后失败：筛选仍只能看到上一次已发布的数据。
- 所需数据缺少一部分：命令报错，不生成看起来成功的空 HTML。
- 从未成功同步：提示先更新，不生成 HTML。
- 环境变量中的 Token 不出现在 SQLite 或同步返回文本中。
- 筛选日期留空：明确报错，不联网，不把运行日当成交易日。
- 同一秒两次写结果：第二个文件带序号，不覆盖第一个。

**Interfaces:**

  - `SyncError(Exception)`
  - `read_token(env: Mapping[str, str]) -> str`
  - `sync_all(connection, *, datasets: tuple[str, ...], env: Mapping[str, str], fetch, finished_at: str) -> str`
  - `fetch(datasets: tuple[str, ...], token: str) -> Mapping[str, int]`
  - `fetch_not_implemented(datasets, token) -> Mapping[str, int]`，抛出 `NotImplementedError`，消息为“Tushare 同步尚未实现”。
  - 成功时返回 `finished_at`。`fetch` 抛出任何异常时先 `abort`，再原样抛出；已发布数据保持不变。

- [ ] **Step 1: Write the failing tests**

```python
def test_failed_fetch_keeps_previous_publication(self):
    connection = open_database(self.path)
    sync_all(connection, datasets=("prices",), env={"TUSHARE_TOKEN": "SECRET-TOKEN-VALUE"},
             fetch=lambda datasets, token: {"prices": 1}, finished_at="2026-10-11 09:00:00")
    def fail(datasets, token):
        raise RuntimeError("upstream failed")
    with self.assertRaisesRegex(RuntimeError, "upstream failed"):
        sync_all(connection, datasets=("financials",), env={"TUSHARE_TOKEN": "SECRET-TOKEN-VALUE"},
                 fetch=fail, finished_at="2026-10-11 10:00:00")
    self.assertEqual(published_datasets(connection), frozenset({"prices"}))
    self.assertNotIn("SECRET-TOKEN-VALUE", Path(self.path).read_bytes().decode("utf-8", "ignore"))

def test_missing_token_does_not_open_batch(self):
    connection = open_database(self.path)
    with self.assertRaises(SyncError):
        sync_all(connection, datasets=("prices",), env={}, fetch=lambda datasets, token: {},
                 finished_at="2026-10-11 09:00:00")
    self.assertIsNone(last_successful_sync_at(connection))
```
